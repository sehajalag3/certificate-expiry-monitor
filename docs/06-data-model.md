# 6. Data model

## 6.1 Entity-relationship overview

Single aggregate in v1:

```
Certificate (table: certificate)
```

(No child tables: one row per tracked certificate. Alerts/counts are derived queries.)

## 6.2 `certificate` table

| Column | Type | Constraints | Notes |
|--------|------|-------------|-------|
| `id` | BIGINT | PK, generated identity | surrogate key |
| `name` | VARCHAR(100) | NOT NULL | 2-100 chars (validated) |
| `type` | VARCHAR(30) | NOT NULL, enum | `TLS_SSL`, `DOMAIN`, `CODE_SIGNING`, `CLIENT`, `EMAIL_SMTP`, `OTHER` |
| `hostname` | VARCHAR(255) | NOT NULL | pattern allows `*.example.com` and `localhost` |
| `issuer` | VARCHAR(100) | nullable | CA name |
| `owner_team` | VARCHAR(80) | NOT NULL | accountable team |
| `environment` | VARCHAR(20) | NOT NULL, enum | `PRODUCTION`, `STAGING`, `DEVELOPMENT`, `QA` |
| `issue_date` | DATE | NOT NULL | must not be in the future |
| `expiry_date` | DATE | NOT NULL | must be after `issue_date` |
| `notes` | VARCHAR(1000) | nullable | free text, searchable |
| `created_at` | TIMESTAMP | NOT NULL | set by `@PrePersist` |
| `updated_at` | TIMESTAMP | NOT NULL | set by `@PrePersist` + `@PreUpdate` |

Derived (never stored): `status` (EXPIRED / EXPIRING_SOON / VALID) and `daysRemaining`,
computed by `ExpiryStatusCalculator` from `expiry_date`, today and
`app.warning-threshold-days`.

## 6.3 Enumerations

- **CertificateType:** `TLS_SSL`, `DOMAIN`, `CODE_SIGNING`, `CLIENT`, `EMAIL_SMTP`, `OTHER`
- **EnvironmentType:** `PRODUCTION`, `STAGING`, `DEVELOPMENT`, `QA`
- **CertificateStatus:** `EXPIRED`, `EXPIRING_SOON`, `VALID` (display labels: Expired /
  Expiring soon / Valid)

## 6.4 Indexes & queries

Default DDL (`spring.jpa.hibernate.ddl-auto: update`) creates no custom indexes; the dataset
scale (hundreds to low thousands of rows) makes scans irrelevant. Important query shapes:

| Query | Shape | Source |
|-------|-------|--------|
| Dashboard counts | `countByStatus`-style derived counts on expiry boundaries | `CertificateRepository` |
| Expiry alerts | `findByExpiryDateLessThanEqualOrderByExpiryDateAsc(today+threshold)` | `CertificateRepository` |
| List search/filter | JPA `Specification` composition (`q` OR-predicate + equality predicates) | `CertificateService` |
| Sorting | property allow-list -> Spring `Sort` | `CertificateController` |

For PostgreSQL production use (`application-postgres.yml`), recommended manual indexes if the
inventory grows beyond ~50k rows: `(expiry_date)`, `(owner_team)`, `(hostname)`.

## 6.5 DDL (as generated, reference)

```sql
CREATE TABLE certificate (
    id           BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name         VARCHAR(100)  NOT NULL,
    type         VARCHAR(30)   NOT NULL,
    hostname     VARCHAR(255)  NOT NULL,
    issuer       VARCHAR(100),
    owner_team   VARCHAR(80)   NOT NULL,
    environment  VARCHAR(20)   NOT NULL,
    issue_date   DATE          NOT NULL,
    expiry_date  DATE          NOT NULL,
    notes        VARCHAR(1000),
    created_at   TIMESTAMP     NOT NULL,
    updated_at   TIMESTAMP     NOT NULL
);
```

## 6.7 Storage choices

| Environment | Store | Rationale |
|-------------|-------|-----------|
| Dev/demo (default) | H2 file `./data/certificate-monitor` (AUTO_SERVER) | zero-install, survives restarts, shared by Maven runs |
| Tests | H2 in-memory (`certmonitor-test`, `uitest`) | isolation + fast; test config in `src/test/resources/application.yml` |
| Production | PostgreSQL (`SPRING_PROFILES_ACTIVE=postgres`) | concurrent writers, backups, managed offerings |
